# Git Worktrees

Git worktree 是 GitHub Copilot app 中最重要的概念之一。它們讓應用程式可以執行多個程式設計工作階段，而不會把所有變更混在同一個資料夾中。

## 白話定義

git worktree 是連接到同一個存放庫的另一個工作資料夾。

把你的存放庫想像成一座共用的藏書館。worktree 就是另一張獨立的書桌，你可以在上面簽出不同的分支並進行工作，而不會干擾主要的書桌。

在 GitHub Copilot app 中，一個工作階段通常會有自己的分支和 worktree。這表示：

- 你的主要簽出內容可以保持整潔，
- 每個工作階段都可以在自己的資料夾中進行變更，
- 平行的工作階段更容易比較，
- 你可以檢視某個工作階段，而不必接受它的變更。

## Worktree、分支與工作階段

| 詞彙 | 初學者的理解 |
|---|---|
| 工作階段（Session） | GitHub Copilot app 的工作區，代理程式會在其中規劃、編輯、測試並回報進度 |
| 分支（Branch） | git 中一條具名的工作線，通常用於一項功能或一個修正 |
| Worktree | 附加到同一個存放庫的獨立資料夾，通常會簽出到某個工作階段的分支 |

應用程式會用你的分支前置詞（預設為你的 GitHub 使用者名稱）加上自動產生的單字，來命名新的工作階段分支，例如 `octocat-bookish-invention`。代理程式可以將分支重新命名以描述任務，例如 `octocat-fix-unread-count`。你可以在 **Settings** > **Sessions** 中變更前置詞。

## 為什麼應用程式使用 worktree

Worktree 有助於讓代理程式的工作保持可檢視且可還原。

例如，一個工作階段可以修正搜尋錯誤，同時另一個工作階段撰寫測試。每個工作階段都可以有自己的資料夾、分支、終端機、瀏覽器預覽和 diff。在決定哪些內容要變成提取要求之前，你可以逐一檢閱。

## 安全檢視檢查清單

當你想查看某個工作階段的 worktree 時，請使用這份檢查清單。

1. 在 GitHub Copilot app 中找到該工作階段。
2. 記下應用程式顯示的分支名稱和 worktree 路徑。
3. 只為了檢視或謹慎編輯而開啟 worktree 資料夾。
4. 確認你的編輯器顯示的是工作階段的分支，而不是主要分支。
5. 在工作階段仍在進行時，避免刪除、重新命名或移動 worktree。
6. 在接受變更之前，先使用應用程式的 diff 檢視。
7. 從工作階段的 worktree 執行驗證命令，而不是從主要簽出內容執行。

以範例應用程式來說，驗證通常從這裡開始：

```bash
cd samples/book-app-web
npm install
npm test -- --run
npm run build
```

如果你在工作階段的 worktree 內，請從該 worktree 的 `samples/book-app-web` 資料夾執行這些命令。

## 不該做的事

除非你確切知道為什麼安全，否則請避免這些動作：

- 不要從 Finder、檔案總管或終端機刪除正在使用中的 worktree。
- 在應用程式仍在追蹤 worktree 資料夾時，不要重新命名它。
- 不要在正在使用中的工作階段 worktree 內手動切換分支。
- 不要把未經檢閱的變更從一個 worktree 複製到另一個。
- 不要假設 worktree 會隔離你電腦上的所有內容。

Worktree 隔離的是檔案和分支。它們不會自動隔離連接埠、本機資料庫、Docker 容器、快取資料夾、環境檔案或背景處理序。

## 連接埠與資源衝突

如果兩個工作階段使用相同的外部資源，它們仍可能發生衝突。

### 範例：Web 伺服器連接埠衝突

範例 Web 應用程式使用 Vite。課程預設的命令使用連接埠 `5173`：

```bash
npm run dev -- --host 127.0.0.1 --port 5173
```

如果兩個 worktree 都在連接埠 `5173` 上啟動應用程式，第二個可能會失敗或選擇不同的連接埠。請為第二個工作階段使用不同的連接埠：

```bash
npm run dev -- --host 127.0.0.1 --port 5174
```

請為瀏覽器索引標籤或畫布預覽加上標籤，以便知道你正在檢視哪個工作階段。

### 範例：共用的本機檔案

如果兩個工作階段讀取相同的 `.env.local`、快取資料夾或位於 worktree 外部的產生檔案，它們可能會互相影響。請優先使用工作階段本機的檔案，並避免在課程範例中放入祕密資訊。

### 範例：容器與服務

如果之後的章節使用容器或本機服務，請為每個工作階段指定唯一的服務名稱、容器名稱、資料庫名稱或連接埠。在啟動另一個工作階段之前，先停止未使用的服務。

## 清理

可能的話，請優先從 GitHub Copilot app 內部進行清理。應用程式知道哪個工作階段擁有哪個 worktree。

清理之前：

1. 檢閱工作階段的 diff。
2. 透過提交、開啟 PR，或只複製已檢閱的變更，來儲存你需要的內容。
3. 停止與該 worktree 相關的開發伺服器、終端機工作和瀏覽器預覽。
4. 關閉在該 worktree 中開啟的編輯器。
5. 在側邊欄中以滑鼠右鍵按一下該工作階段。選取 **Archive** 以保留工作階段歷程記錄，或選取 **Delete** 以移除工作階段及其檔案。刪除之前，應用程式會將未提交的變更備份到復原分支。

如果 worktree 是在應用程式之外建立的，請在檢查分支和路徑之後，才使用一般的 git 命令：

```bash
git worktree list
git worktree remove path/to/worktree
git branch --delete branch-name
```

只有在工作已合併或刻意捨棄之後，才使用 `git branch --delete`。如果 git 拒絕刪除分支，請停下來檢查原因。

## 疑難排解

| 症狀 | 檢查項目 |
|---|---|
| 應用程式找不到工作階段資料夾 | worktree 可能已被手動移動或刪除 |
| 測試在一個資料夾中通過，但在另一個資料夾中失敗 | 分支、相依套件安裝狀態、環境變數和產生的檔案 |
| 瀏覽器預覽顯示錯誤的變更 | 瀏覽器索引標籤指向錯誤的連接埠或工作階段 |
| 兩個工作階段編輯相同的檔案 | 暫停其中一個工作階段，比較 diff，並選擇作為依據的來源 |
| 清理失敗 | 停止執行中的處理序、關閉編輯器，並先使用應用程式的清理途徑 |
